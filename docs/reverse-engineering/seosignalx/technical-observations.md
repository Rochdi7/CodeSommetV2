# Technical observations — seosignalx.com

Captured 2026-10-26 through normal anonymous browser access and plain HTTP GETs of public URLs. No endpoint was called outside of what the pages themselves request while rendering. Confidence levels: **H** = directly observed, **M** = strong inference from several observations, **L** = weak inference.

## Implications for our build

- Their app logic runs mostly client-side behind a thin `/api/proxy`. That is cheap to run, but it also explains the poor SEO (OBS-001, OBS-012). Our Laravel stack already server-renders, which is an advantage to keep.
- The heavy features (keyword volumes, SERP and LLM mentions, authority metrics, PSI) depend on third-party APIs. See [data-model-and-algorithm-notes.md](data-model-and-algorithm-notes.md).
- The "Patches" WordPress plugin is a distinct product surface (remote fix application). Treat it as a separate project, not as part of the tool suite.
